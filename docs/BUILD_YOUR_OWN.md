# 把它做成你自己的产品：独立开发路线

## 路线 A：周末级原型

目标：验证一个城市、一个官方数据源是否能形成可用查询。

1. 选择一个官方公开数据栏目。
2. 手工登记 20—50 条样本，逐条保留原文链接和发布日期。
3. 建立最小数据表：来源、主体、事件、时间、状态。
4. 做一个搜索框和结果详情页。
5. 页面显示“信息来源、发布时间、采集时间、证据状态”。
6. 找 5—10 位真实用户完成查询任务，记录失败点。

样本数量只是开发验证规模，不应伪装成该城市完整覆盖。

## 路线 B：可持续的城市产品

- 自动化合法来源更新；
- 增量抓取和变更检测；
- 实体消歧和冲突标记；
- 纠错、申诉和审计；
- 官方渠道导航；
- 搜索引擎可索引的来源页面；
- 数据新鲜度和质量看板。

## 路线 C：跨城市产品

在每个新城市接入前，先建立数据源档案：
- 发布机构与栏目；
- 数据格式和更新规律；
- 访问和使用条款；
- 历史覆盖范围；
- 解析稳定性；
- 地方举报办事入口；
- 纠错联系人或公开渠道。

不要因为技术上能抓取，就认定可以合法长期使用。

## 本地运行建议

本仓库当前是项目文档起点，尚未提供可直接运行的完整应用源码。开发者可以自行选择技术栈，按技术架构文档建立最小实现。

## 发布前检查清单

- [ ] 所有数据都有可追溯来源。
- [ ] 公开页面区分官方信息、媒体报道和用户反馈。
- [ ] 同名门店不会被随意合并。
- [ ] 有发布时间、采集时间和更新状态。
- [ ] 有纠错与申诉入口。
- [ ] 用户材料默认私密且有删除机制。
- [ ] 举报需要用户自行审阅并确认。
- [ ] 广告与事实展示隔离。
- [ ] 不存在收费删帖、保护费或负面信息交易。
- [ ] 已核验当地法律、平台规则和数据来源条款。

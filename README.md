# 狗上桌（Dog on Table）

> 一个面向公众的餐饮食品安全信息查询与消费者行动项目。任何开发者都可以 Fork、下载、独立部署、改造，或将其发展为自己的开源作品与创业产品。

**项目性质：公开项目构想与独立开发起点，不是团队招募，不要求加入发起方，也不要求向发起方汇报。**

## 为什么值得做

消费者想了解一家餐厅的食品安全状况时，公开信息往往分散在监管公示、行政处罚、抽检通报、媒体报道和投诉渠道中。普通人难以检索、理解、比较和持续跟踪。

「狗上桌」希望把依法公开、可核验的餐饮食品安全信息整理成更容易查询和理解的公共信息服务，并帮助消费者找到正确、正式的反馈与举报渠道。

它既是一个公共价值项目，也是一道可以独立完成的产品题目：搜索、数据工程、信息抽取、多模态识别、地图、内容传播、移动端产品和本地商业服务都有发挥空间。

## 你可以怎样使用这个项目

- **独立开发**：下载源码或 Fork 仓库，做成自己的网站、小程序、App、浏览器插件或城市服务。
- **独立运营**：选择一个城市、一个数据源或一个消费场景，从小范围开始验证真实需求。
- **作为作品集**：把它做成完整的 AI、数据工程或全栈项目。
- **发展为创业产品**：在遵守法律、平台规则、数据授权和消费者权益的前提下，探索广告、赞助、合规企业服务等模式。
- **只借鉴方法**：可以参考项目中的公开技术思路，不必沿用品牌、界面或全部设计。

本仓库不设统一运营组织。不同开发者可以做出彼此独立的实现和商业产品。

## 主要产品形态

1. **Web 查询站**：按餐厅名称、地址、城市、行政区查询公开食品安全信息。
2. **微信小程序**：面向普通消费者的轻量查询、收藏和信息反馈入口。
3. **移动 App**：订阅关注门店、查看信息更新、保存消费记录和官方办事入口。
4. **城市专题页**：围绕一个城市或商圈整理公开监管信息。
5. **抖音 / 公众号内容**：将已核验的公开信息转化为科普、查询教程和城市观察内容。
6. **开发者工具 / API**：为合规的研究、媒体和企业应用提供来源清晰的数据接口。

## 核心功能建议

- 餐饮主体检索与实体消歧：避免同名门店、分店和主体混淆。
- 官方公开信息归档：监管公示、抽检结果、行政处罚、许可信息等。
- 来源与证据展示：原始链接、发布机构、发布时间、抓取时间、证据状态。
- 历史变化追踪：展示信息更新，不把旧记录误写成当前状态。
- 消费者反馈：允许提交线索，但与官方结论严格区分。
- 正式举报指引：按地区展示市场监管部门官方投诉举报渠道；提交前由用户核对并确认。
- 纠错与申诉：为商家提供事实纠错、补充材料和联系维护者的渠道。

## 重要原则

### 事实与证据

- 只使用合法公开、获得授权或用户主动提交且有处理依据的信息。
- 每条记录尽量保留原始来源、时间、适用对象和证据链。
- 明确区分「官方已发布」「媒体报道」「用户反馈」「模型推断」「尚待核实」。
- 不把投诉数量、网络传言或模型评分写成违法违规结论。
- 不因一次历史处罚就断言门店当前不安全；展示时间、事项和后续状态。
- 提供纠错、申诉和下架复核机制。

### 举报与消费者行动

系统可以提供官方渠道导航、材料清单和举报文本辅助整理，但不得自动批量举报、伪造证据、诱导恶意投诉或替用户作出事实判断。任何正式提交都应由用户审阅并主动确认。

### 商业化边界

项目可以研究广告、合规赞助、企业合规工具、数据整理服务和技术服务。**禁止以删除负面信息、压制举报、改变风险等级或不曝光为条件收费。** 不得向商家索取所谓「保护费」，不得以曝光相威胁，不得将投诉举报变成勒索工具。

## 技术方向

建议采用可替换、可分阶段的架构：

- 数据接入：官方公开网页、开放数据、授权数据、人工提交。
- 采集与更新：定时任务、增量抓取、变更检测、来源登记。
- 解析与归一：OCR、网页解析、实体匹配、地址标准化。
- 证据层：原文快照、来源 URL、时间戳、哈希、处理日志。
- 检索层：关键词检索、地理检索、同名消歧、时间线。
- 应用层：Web API、Web、小程序、App。
- 质量层：抽样复核、冲突检测、撤回机制、数据新鲜度监测。

详细方案见 [docs/](docs/)。

## MFI 方法思路（公开概要）

项目可以借鉴多源信息发现（MFI）的思路：不预先锁定单一来源或固定关键词，而是从公开信息中发现主体、事件和需求线索；将多来源表达聚合到候选事件；补充时间、地点、主体和原始证据；再用冲突检测、反例搜索和证据等级控制结论。

这里公开的是方法框架，不意味着任何自动识别结果天然真实。具体记录仍需来源追溯、适用范围判断和纠错机制。

## 变现探索

- 本地生活相关的合规广告（明确标识广告，不影响查询排序和事实判断）。
- 企业食品安全自查、培训、整改记录管理等工具服务。
- 面向媒体、研究者和机构的合规数据整理与 API 服务。
- 公益基金、透明赞助和研究合作。

商业收入不得购买信息删除、负面结果隐藏、举报阻断或评级操纵。

## 从哪里开始

推荐个人开发者先做一个城市、一个公开数据源、一个可检索页面：

1. 确定当地可合法访问的官方公开信息源。
2. 建立来源登记与数据字段规范。
3. 完成小规模采集、实体去重和原文链接展示。
4. 加入更新时间、证据状态和纠错入口。
5. 找真实用户验证查询是否有用，再决定是否扩展小程序、App 或商业服务。
